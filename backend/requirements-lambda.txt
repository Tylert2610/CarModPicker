# The shared WebbPulse package, published only to CodeArtifact. It has to be
# here as well as in `requirements.txt`, because this is the file the Lambda
# image and the deploy zip install: a runtime pin present only in the other file
# passes every test and then fails at import inside the image.
# `tests/test_requirements_lambda_subset.py` is what stops that recurring.
#
# `otel` and `aws-otel` are both live as of row 16: the domain functions export
# spans to the X-Ray OTLP endpoint, and `aws-otel` is the SigV4 signing exporter
# that endpoint requires. This is the file the image installs, so an extra
# present only in `requirements.txt` would pass every check and then fall back
# to the unsigned exporter inside the running function, which is a silent 403
# rather than a failure. `dynamodb` carries the botocore error handlers the
# composition root installs; the package imports botocore lazily inside them, so
# it costs nothing at import time.
#
# `security` is what row 19 added: `webbpulse.security` now provides this app's
# password hashing and JWT signing, replacing the local bcrypt and PyJWT calls.
# It pulls PyJWT and bcrypt, both of which were already pinned below and stay
# pinned here, because this file is the resolved set and the package's own
# ranges must not be allowed to float a different major into the image.
#
# `identity` is what row 5 of the identity adoption plan adds:
# `webbpulse.identity` now serves the M1 discovery documents and the M2 to M4
# flows on the `identity` function, mounted by `app/composition/identity.py`.
# The extra carries `PyJWT[crypto]`, which is PyJWT plus `cryptography`: the JWK
# the JWKS publishes is built from the DER SubjectPublicKeyInfo that
# `kms:GetPublicKey` returns, and `cryptography` is what parses it. Both are
# already resolved below and stay pinned there, `PyJWT` now with its `crypto`
# extra so the dependency is declared rather than inherited from `webauthn`.
#
# `oauth` and `passkeys` are what row 9 adds, and the version bump to 0.16.0 is
# what carries the routes behind them.
#
# `oauth` pulls `httpx`, which is the only outbound HTTP this application makes:
# the provider token exchange and userinfo calls of the package's M6 flow.
# `app/composition/identity.py` now supplies both an `oauth_states` and an
# `oauth_links` store, and `terraform/identity.tf` created both tables in the
# module's default map, so the five OAuth routes mount as soon as a provider
# carries a client id.
#
# `passkeys` pulls `py_webauthn`, which the package imports lazily inside the
# methods that need it, so it costs nothing on a cold start that never sees a
# passkey. This product already depends on `webauthn` below for its own legacy
# WebAuthn routes, so the extra declares a dependency that was already resolved
# rather than adding one.
#
# 0.17.0 adds one route and nothing else: `GET /api/auth/passkeys/availability`,
# anonymous, unconditional, answering `{"enabled": bool, "passwordless": bool}`
# from the two `IDENTITY_PASSKEYS_*` settings. It is the passkey counterpart of
# 0.16.0's `oauth/providers` and mounts in every deployment including this one
# with both flags off, where it answers false to both. No new dependency and no
# new extra, so the pin moves and the resolved set below does not.
