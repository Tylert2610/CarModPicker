# The shared WebbPulse package. It lives only in CodeArtifact (domain
# `webbpulse`, repository `python`, us-west-2), not on PyPI, so anything that
# installs this file needs a CodeArtifact token first. CI gets one from the
# `aws codeartifact login --tool pip` step in `backend-ci.yml`.
#
# Extras, and why each one: `fastapi` for the app factory and `run_uvicorn`,
# `otel` for `configure_tracing`, `dynamodb` for the botocore error handlers
# `register_error_handlers(dynamodb=True)` installs. That extra used to be
# absent because CarModPicker has its own repository layer and secret loader,
# but the handlers are what turn a DynamoDB throttle into a 503 with
# `Retry-After` instead of a flat 500, so it earns its place now. It adds no
# new pins: boto3 is already pinned below.
#
# `aws-otel` is what row 16 added, and it is not optional once tracing is on.
# The X-Ray OTLP endpoint authenticates with SigV4 and answers 403 to an
# unsigned POST, and the OTLP exporter retries a 403 in silence, so the symptom
# of leaving this out is traces that never appear with nothing in the logs to
# say why. The extra carries `aws-opentelemetry-distro`, from which only the
# `OTLPAwsSpanExporter` class is used: `webbpulse.otel` builds the pipeline
# itself rather than launching under `opentelemetry-instrument`, so the
# distribution is a library here and not a wrapper. It is additive to `otel`
# rather than a replacement for it, and both must be present.
#
# `security` is what row 19 added: `webbpulse.security` now provides this app's
# password hashing and JWT signing, replacing the local bcrypt and PyJWT calls.
# It pulls PyJWT and bcrypt, both of which were already pinned below and stay
# pinned here, because this file is the resolved set and the package's own
# ranges must not be allowed to float a different major into the image.
webbpulse[fastapi,otel,dynamodb,aws-otel,security]==0.11.0
